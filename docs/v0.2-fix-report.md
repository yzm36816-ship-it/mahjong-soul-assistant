# v0.2 实时监控修复

## 已确认的原因

1. v0.1 只对人工确认后的牌面执行分析，下一次画面变化又使确认失效。因此即使读取继续，用户也始终看到待校对。
2. 实际 Steam 游戏在旧 HWND / PrintWindow 截图路径下返回纯黑图，普通 Qt 测试窗口无法暴露这个兼容问题。
3. 查看风险依据会调用 stop_live，部分界面操作因此停止实时更新。

## 修复

- 新增绑定特定 HWND 的 Windows Graphics Capture 后端，成功读取当前真实 Steam 游戏图形画面；不使用显示器捕获或全桌面回退。
- 每 500ms 调度下一次读取，任务未结束不并行重入；暂时读取失败自动重试，暂停按钮保持可用。
- 连续稳定的牌面可自动产生条件性初判，不需要人工确认。自动识别结果与人工事实分别存储。
- 打开预览 / 风险详情不会暂停实时监控；帧数、时间、风险列表持续更新。
- 横置牌只作为疑似立直证据。等待候选依据荣和振听、可见牌数量以及单骑、双碰、顺子形状、国士必要条件生成，不做概率排名或完整手牌还原。
- 原版与新版分目录，原始素材和原版数据保留。

## 验证

- 36 项测试通过，包括自动恢复、出牌后刷新、界面计时器继续运行、暂停按钮、牌数冲突抑制、筋的其他等待可能。
- 69.57 秒参考视频以 0.5 秒步长跑完，共 139 帧；没有调用人工确认，92 帧生成自动风险行。
- 此参考视频末尾结算画面不再生成风险行；这不等于所有结算界面均能识别。
- 自动风险帧数用于检验流程可运行，不代表牌识别或听牌判断准确率；视频与模板校准素材相关。
- 已实测真实 Steam 正常三麻牌桌：最近一次连续读取 8 帧，7 帧生成条件性自动风险提示；末帧为东 3 局、本人 51900 分、余 9 张。仍有手牌与舍牌漏识别，不能将流程通过当作识别完整或判断准确。
- 排除了底部小尺寸副露被误计为手牌的问题，并补充人工核验过的实际窗口牌面模板；这些素材属于校准数据。

## 仍有限制

- 尚无训练和校准过的默听 / 真实等待预测模型。
- 自动副露识别未完成，未人工填写时不使用副露数量作强结论。
- 横置牌检测缺少足够的真实立直正例；必须保留“疑似”标记。
- 不能仅凭公开画面知道真实等待牌；候选可能很多。
